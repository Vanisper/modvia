# Modvia 设计

## 定位

Modvia 是独立的 TypeScript 模型层基础库。它把不可信外部表示转换为可信业务模型，并按同一套声明将模型编码回外部表示。

项目关注模型边界，不负责数据传输、Service 组织、共享缓存或页面状态。HTTP 客户端、查询库和 UI 可以通过普通 Codec 接口组合，但不进入核心依赖。

## 设计原则

### 普通对象是完整能力

不继承基类也能使用字段校验、嵌套模型、数组、别名、自定义转换和双向编码。普通对象输出便于字面量测试、不可变更新、结构化传输与缓存组合。

### class 是构造与行为增强

class 输出通过工厂创建。工厂接收已经校验和转换的完整数据，可以执行真实构造器、恢复原型并附加领域行为。核心不绕过构造器，也不向对象动态安装业务方法。

两种输出共享数据契约，但不强行统一行为写法。普通对象使用领域函数，class 使用实例或静态方法。

### 双向转换使用同一份字段声明

解码和编码都读取字段定义。核心不通过 `Object.keys(new Class())` 推导协议，不依赖实际值上的 `toJson()`，也不把 TypeScript 类型标注当作运行时校验。

### 复制由构造语义决定

对象与数组在解码、编码时形成新容器；自定义 Codec 决定其标量或值对象的转换与所有权。核心不进行无差别深拷贝，也不默认深度冻结模型。

## 首个闭环

首个版本只交付一条完整、可独立使用的路径：

1. 声明字段和外部字段别名。
2. 解码字符串、有限数字、布尔值、字符串枚举与 ISO 日期时间。
3. 递归解码和编码嵌套模型与模型数组。
4. 返回带输入路径的结构化校验错误。
5. 通过可选工厂输出 class 实例。
6. 从公共入口生成 ESM 产物与 TypeScript 声明。

首轮字段均为必填，null 除非字段 Codec 明确接受，否则视为非法。对象输入只接受普通对象形状；未知输入字段在解码时剥离，编码只输出声明字段。

### 暂不进入核心

- 可选、可空、默认值与局部 Patch 推导；
- 跨字段校验、异步校验与远程唯一性检查；
- class 继承、装饰器和私有状态的自动映射；
- 循环对象图、身份映射、脏跟踪与懒加载；
- UI 表单、表格、权限与展示元数据；
- Service、CRUD、HTTP、缓存与框架绑定。

这些方向需要各自明确的语义，不通过预留万能配置字段提前占用设计。

## 公共概念

| 概念                    | 职责                                   |
| ----------------------- | -------------------------------------- |
| `Codec<T, Encoded>`     | 在模型值与外部表示之间双向转换         |
| `Model<Data, DTO, Out>` | 对象模型 Codec，并支持派生 class 输出  |
| `ModelValidationError`  | 聚合字段错误，保留输入路径与稳定错误码 |
| `defineModel`           | 声明对象字段并创建普通对象模型         |
| `defineCodec`           | 创建可嵌套使用的自定义双向 Codec       |
| `field`                 | 为字段 Codec 指定外部字段名            |
| `arrayOf`               | 组合列表 Codec，保留数组下标路径       |
| `withFactory`           | 从已校验数据构造 class 或其他增强输出  |

类型工具 `InferData`、`InferDTO` 与 `InferModel` 分别取得内部数据、外部 DTO 和实际输出类型。

## 模块规划

```text
packages/modvia/
├─ src/
│  ├─ core/
│  │  ├─ codec.ts       Codec、数组组合与自定义 Codec
│  │  ├─ errors.ts      校验错误与错误路径
│  │  ├─ model.ts       字段遍历、模型构造与工厂派生
│  │  └─ types.ts       公共类型与类型推导
│  ├─ fields.ts        首版标量与日期时间 Codec
│  └─ index.ts         唯一公共入口
├─ scripts/
│  └─ artifact-smoke.ts  打包产物冒烟检查
├─ tests/              公共行为与类型消费测试
├─ README.md           使用方式与行为边界
├─ package.json
├─ tsconfig.json
└─ vite.config.ts
```

`core` 内部按职责拆分，外部只从包入口消费。后续字段能力优先围绕现有 Codec 组合，不增加平行执行入口。

## 执行契约

### 解码

```text
unknown 输入
→ 检查对象形状
→ 按字段定义校验与转换
→ 递归构造嵌套数据
→ 聚合错误或返回完整数据
→ 可选工厂构造最终输出
```

任一字段非法时不返回部分模型。自定义 Codec 抛出的校验失败由外层补充字段路径；其他异常不伪装成校验结果。

### 编码

```text
模型或增强输出
→ 只读取声明字段
→ 递归编码嵌套值
→ 应用字段别名
→ 返回新的 DTO 容器
```

编码不信任静态类型声明，仍会执行字段 Codec 的编码检查。首轮只输出声明字段，不提供动态的 `partial`、`mode` 或 `raw` 开关。

### class 工厂

工厂只接收完整数据，不接收原始 DTO。默认编码按字段结构读取输出，因此公开只读字段的 class 可以直接参与；依赖私有状态的类需要自定义 Codec，而不是让核心猜测内部状态。

## 验证策略

测试围绕公共入口和实际消费者行为，不逐项覆盖内部辅助函数：

- 同一组 DTO fixture 验证普通对象与 class 输出；
- 覆盖字段校验、别名、嵌套、数组和双向编码；
- 检查错误路径、未知字段剥离和非法列表输入；
- 验证工厂在完整数据之后执行，以及实例方法可用；
- 用少量类型断言验证 DTO、Data 与 class 输出推导；
- 构建后从打包产物运行一次完整解码与编码。

不引入覆盖率门槛、内部状态快照或大规模组合矩阵。后续新增语义先补公共行为用例，再扩展实现。
